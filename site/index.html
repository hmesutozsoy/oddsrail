Built from the things the raw API gets wrong

Every one of these was found by driving the venues live, then encoded so an agent never has to rediscover it.

01 — ORDERBOOKS

The book arrives worst-first

Polymarket's raw orderbook lists bids ascending and asks descending, so bids[0] is the worst level. Every model's prior says index 0 is best.

normalises both venues to best-first and walks the book to quote what a size actually costs.
02 — REJECTIONS

Rejections don't raise

The exchange models a rejected order as a return value, not an exception. Reported carelessly, a rejection reads to an agent as a resting order.

branches on it — accepted: false, nothing attributed, and an unrecognised response shape is never reported as posted.
03 — GEOGRAPHY

Geoblocks look healthy until the order

Restricted jurisdictions are enforced at order placement. Public reads answer normally, so everything works right up to the trade.

classifies every failure shape — jurisdiction, network filter, ISP interstitial — and gives the agent an actionable hint instead of a retry loop.
04 — YOUR OWN FILLS

"Account trades" returns everyone's

The SDK call that sounds like your fills returns the market's public tape.

reads the operator's activity feed by wallet, with tx hashes.
05 — KALSHI

Kalshi has no yes/no side

Everything is quoted from the YES book as bid/ask; prices are dollar strings, not cents. Getting the translation backwards silently takes the opposite position.

lets the agent say outcome=no, action=buy and translates it — tested exhaustively, not by example.
06 — CROSS-VENUE

A price gap is not an edge

Identical wording on two venues does not mean identical settlement.

pairs candidates by similarity and close date, then audits resolution sources, UMA status and structure before anyone calls it arbitrage.

How it pays for itself without charging you

custody
None. You run the server; your keys sign your orders on your machine. Nothing is proxied and nothing is stored.
fees
0 bps. Orders carry a builder code registered at 0 bps maker / 0 bps taker — no fee is added to any trade.
attribution
The code is placed in the CLOB V2 order struct before signing, so attribution is on-chain in every OrderFilled event. The project earns only a share of Polymarket's weekly builder pool, which Polymarket pays out of its own program.
override
Set ODDSRAIL_BUILDER_CODE to your own code and the share accrues to you instead. The default is a default, not a lock-in.
status
Verified in Polymarket's builder program, with the attribution pattern for self-hosted, non-custodial tools confirmed by their builder team.

Kalshi's REST API has no attribution field, so Kalshi flow is never attributed or monetised. It is in oddsrail for coverage, not routing revenue.

# the whole configuration
export ODDSRAIL_DRY_RUN=1          # default: simulate
export ODDSRAIL_BUILDER_CODE=0x…   # optional: yours
export POLYMARKET_PRIVATE_KEY=…    # only to trade
export KALSHI_KEY_ID=…             # only for Kalshi private

# then, in any MCP client
"find markets about the world cup and
 quote the cost of 100 shares on the favourite"
